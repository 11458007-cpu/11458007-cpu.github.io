# 部署說明：將 `code.gs` 發佈為 Web App 並完成授權

以下步驟示範如何把單一檔案的 Google Apps Script (`code.gs`) 部署為 Web 應用，並示範第一次授權與常見權限問題處理。

準備：請確認你有一個 Google 帳號，並且該帳號能存取目標 Google Drive 資料夾（ID 寫在 `code.gs` 的 `RAW_FOLDER_ID`）。

步驟：

1. 開啟 Apps Script 編輯器
   - 前往 https://script.google.com/ 並登入你的 Google 帳號。
   - 點「新增專案」或打開現有專案。

2. 建立/貼上程式碼
   - 在編輯器左側，建立一個 `Code.gs` 檔案（或使用預設的 `Code.gs`）。
   - 打開工作區裡的 [6/code.gs](6/code.gs)（本 repo），將內容複製並貼到 Apps Script 的 `Code.gs`。
   - 確認 `RAW_FOLDER_ID` 的值：若你有完整的 folder id，可以把開頭的 `=` 移除或保留（程式會自行處理）。最重要的是該資料夾必須能被執行腳本的帳號存取（擁有或已分享給該帳號）。

3. 存檔並命名專案
   - 點左上「無標題專案」，給專案一個易懂名稱（例如：My-Notepad-WebApp）。

4. 初次執行以觸發授權提示（建議）
   - 在編輯器選單中選 `執行` -> `loadNote`（或 `saveNote`）來觸發授權流程。
   - 系統會跳出帳號與權限授權畫面，請選擇你要用來執行腳本的帳號。
   - 會要求權限類型，例如「查看和管理您在 Google 雲端硬碟上的檔案」。允許後授權即完成。
   - 如果出現「此應用程式尚未驗證」訊息，點選「進階」->「前往 <專案名稱>（不安全）」，然後允許權限。

5. 發佈為 Web 應用
   - 點右上「部署」->「新增部署」或「管理部署」->「新增部署」。
   - 選擇「Web 應用程式」類型。
   - `說明`：輸入簡短描述（例如：Notepad web app）。
   - `執行應該由`（Execute as）：選 `我（專案擁有者）`，這樣腳本會以你（擁有者）的身分存取 Drive（必要條件，否則使用者無法透過你的帳號存取私有資料夾）。
   - `應用程式可存取者`（Who has access）：
     - 測試個人使用：選 `只有我`。
     - 與其他有 Google 帳號的使用者共享：選 `任何擁有 Google 帳號的使用者`。
     - 若要公開（任何人包含未登入者）：選 `任何人`（注意：公開執行仍以你帳號執行，但開放度較高，請謹慎）。
   - 點「部署」，系統會回傳一個 Web 應用 URL。

6. 開啟 Web App 並測試
   - 使用部署回傳的 URL 開啟網頁。
   - 頁面會載入 `記事本.txt`（若無則自動建立），可在編輯區修改，點 `Save` 儲存。

授權與存取重點
- `Execute as: Me` 是關鍵：若你要讓 Web App 讀寫你指定的 Drive 資料夾，務必要選「以我執行」。
- 資料夾權限：若資料夾不是你擁有，請把該資料夾分享給執行腳本的 Google 帳號（腳本擁有者或執行者），否則會出現 `Folder not found` 或權限錯誤。
- 授權範圍：腳本會請求 Drive 存取權限，第一次授權時依照指示完成即可。若使用非驗證的私人應用，可能要點選「進階」->「前往（不安全）」以繼續。

除錯建議
- 若網頁顯示空白或 `載入失敗`：在 Apps Script 編輯器的 `執行` 或 `記錄` 查看錯誤訊息；也可在瀏覽器開發者工具觀察 console。
- 若出現 `Folder not found`：檢查 `RAW_FOLDER_ID` 是否正確（ID 長度通常為 33 字元），確認該資料夾已分享給腳本執行者。
- 若出現授權錯誤：在 Apps Script 編輯器點選 `查看` -> `執行記錄` 或手動執行 `loadNote()` 以重新觸發並允許權限。

額外建議
- 若要多人共用而避免「進階 -> 前往（不安全）」提示，需在 Google Cloud Console 設定 OAuth 同意畫面並送驗（較複雜，適用於公開大量使用者的情況）。
